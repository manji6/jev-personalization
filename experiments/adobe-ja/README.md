# WKDY公開ページを使ったJev小規模検証

2026-10-30（日本時間）。実APIへのPOSTは6件、再試行なし、すべてHTTP 200。
これは合成履歴の動作確認であり、実閲覧者の精度・購入率・施策効果の検証ではない。

## 観測と入力

指定サイト https://adobe.customer-experience.dev/ja/ はWKDYというアパレル・ギアのECサイトだった。
トップ、ストレッチスーツジャケット、吸汗速乾ポロシャツ、コミュートランニングシューズ、コミューターブリーフケース、初心者ランナー応援キャンペーンの公開HTMLを取得した。

6ページとも取得HTML内にJSON-LDはなく、og:titleとog:descriptionから名称・説明を抽出できた。meta descriptionとtitleも存在した。JSON-LDがあるサイトへの抽出実装は今回作っていない。ブラウザ実行後の動的なJSON-LD追加は未確認。リンク先は末尾スラッシュ付きへリダイレクトされた。

ページ名称・説明は実情報。閲覧順序・表示秒数・配信済み状態はすべて人工的に設定した。ページ全文、HTML、フォーム入力、個人情報、URLクエリはJevへ送っていない。取得元はpage-metadata.json、HTMLとハッシュはsources/およびpage-metadata.jsonに残した。

## 仮の施策と質問

事前登録コンテンツ候補は実在の「初心者ランナー応援キャンペーン」。
マーケターの文の例は「通勤ランに関心を示す人へ、このキャンペーンを紹介したい」。
Q1: 閲覧履歴には、通勤ランに関心があることを示す行動がありますか？
Q2: 閲覧履歴には、ランニング初心者向けの情報に関心があることを示す行動がありますか？

Q1のみを条件にする広い施策と、初心者向け情報への関心も求めるQ1 AND Q2の狭い施策を別々にコードで評価した。狭い条件を元の文から自動生成できたという意味ではない。口語からの変換は今回も人手で、未実装・未検証。

Noulはp>0.7をyes、p<0.3をno、その間を未確定とした。確率を掛け合わせない。施策の表示済み・閉じた状態は全件falseという仮定。実SDKの表示や制約機能は実装していない。

## 読み取れること・課題

- 同テーマの反復閲覧と服だけの閲覧は区別できた。シューズ閲覧だけを初心者向け情報の関心と同一視しなかった。
- シューズ2秒でもQ1=.90、60秒でも.91。今回の質問はページの主題を強い関心の根拠にしており、短時間の偶然の遷移を防げていない。最低表示時間・複数閲覧等の確定条件をコードで先に適用する案を、別の未使用ケースで検証する必要がある。閾値の秒数は未合意で、今回の結果に合わせて設定していない。
- トップだけの情報不足ケースは.5付近にはならず、低確率になった。「関心がない」と「判断材料がない」は同じではない。アプリ側に観測不足の保留状態が必要。
- ブリーフケース中心でも一度のシューズ閲覧でQ1=.91。他の関心が優勢か・今何を案内すべきかをこの質問は測っていない。施策優先順位は別に決める必要がある。
- Q2が測るのは初心者向け情報への関心であり、その人が初心者である確率ではない。
- このサイトはJSON-LDの検証題材にはならなかった。配列・@graph・@id・SPAの対応や表示時間計測の実装も別途必要。

## 保存物と再実行

- cases.json: 期待するレビュー観点、実情報と合成の区分、正確な要求本文。
- results.jsonl: 各要求と生の応答文字列、HTTP状態、実返却モデル、確率、usage、時刻、遅延。
- page-metadata.json / sources/: 公開ページの抽出結果と取得HTML。
- openapi.snapshot.json / models.snapshot.md / primitives.snapshot.md: 検証時に取得した公式仕様。
- probe.py: 標準ライブラリによる実験用抽出と実API呼び出し。JSON-LDが存在する場合はフォールバックせずレビューを求めて止まる。製品SDKではない。

python probe.py は保存済みHTMLから入力を生成する。python probe.py --run は有料APIを呼ぶが、results.jsonlがあれば重複実行を拒否する。キーはJEV_API_KEYをBearer認証に使用し、保存・表示しない。自動再試行はない。実験ログはユーザーが依頼した記録であり、本番の閲覧者履歴DBを実装したものではない。
