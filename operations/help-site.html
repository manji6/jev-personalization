ヘルプサイトの保守 ​

このヘルプは、リポジトリのhelp/にあるMarkdownをVitePressでビルドし、GitHub Pagesで公開しています。アプリのサーバーやAPIキーを使わない静的サイトです。生成ツールはVitePress 2.0.0-alpha.21を依存ロックで固定しています。更新時はリンク検査とブラウザ確認を行います。

編集する ​

各ページ下部の編集リンクから提案するか、ローカルでMarkdownを編集します。画面例はhelp/public/images/、メニューはhelp/.vitepress/config.mtsです。

sh
npm ci
npm run help:dev

ローカルに表示されるURLをブラウザで開きます。開発サーバーは127.0.0.1に限定します。

ビルドして確認する ​

sh
npm run help:build
npm run help:preview

内部リンク切れはビルドでエラーにします。検索、メニュー、コードのコピー、スマートフォン幅も確認してください。

GitHub Pagesへ公開する ​

変更をコミットし、作業ツリーを空にしてから実行します。GitHubへのPushとPages設定ができる権限が必要です。

sh
npm run help:publish

ビルド済みファイルだけをgh-pagesへ、通常の履歴を保ったPushで更新します。初回だけPagesの配信元をgh-pagesのルートに設定します。既存のPages設定が異なる場合は、無断で置き換えず停止します。

公開先は https://manji6.github.io/jev-personalization/ です。GitHub側のビルド・配信完了まで少し時間がかかります。

初回有効化だけ403になる場合 ​

GitHubの接続にPages設定の編集権限がない場合、ファイルのPushは成功しても初回有効化だけ失敗することがあります。リポジトリ管理者がSettings → Pagesを開き、Sourceに「Deploy from a branch」、Branchに「gh-pages」、フォルダーに「/ (root)」を選んでSaveします。APIキーや追加トークンを本文へ貼る必要はありません。

一度配信元を設定すれば、以後はgh-pagesへのPushでヘルプを更新できます。Pages設定APIを使わず公開ファイルだけ更新する場合はnpm run help:publish -- --files-onlyを使います。公開URLで表示を確認してから公開完了と扱ってください。

アプリの本番反映との違い ​

ヘルプの公開はgh-pagesだけを更新します。アプリのProductionへコードを配置したり、DBを移行したりしません。

アプリの確認版コミットを変えた場合は、別途Previewへ配置し、確認後にProductionへ進めます。ヘルプを公開したことを、アプリの本番リリース済みという意味には扱いません。
