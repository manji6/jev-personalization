# 診断パネルを読む

「なぜ表示されたか」「なぜ表示されないか」を、実際に操作しているブラウザで調べます。サイトの編集権限が必要です。

## 開き方

管理画面の「動作確認」で対象URLを入力し、実サイトで診断を開始します。対象サイトのSDKと管理画面を開いたままにしてください。

サイト側に一時的なパネルを表示します。ブラウザ拡張は不要です。認可はサイトとOriginを限定し、15分間有効です。管理者トークンやパスキー情報をサイトへ渡しません。

## 見られるもの

| タブ       | 内容                                                                |
| ---------- | ------------------------------------------------------------------- |
| 現在の状態 | 同意・計測・表示時間・現在のページ等                                |
| 閲覧・行動 | このブラウザで観測したページ、取得元、追加イベントや状態            |
| 判定履歴   | 判断API要求・応答、Jev用state/questions、判定値、確定条件と表示制約 |

履歴は診断用にサーバーへ保存しません。通常のAPI要求を観察し、パネルを開いたからといって追加のJev問い合わせをしません。診断も同意を迂回しません。

## 表示されないときの読み方

- **メタデータ送信が未承認**：サイト設定で送信を有効にしたか確認。
- **有効閲覧が不足**：表示時間と件数を確認。背景タブの時間は表示中の時間へ含めない。
- **対象ページ外**：収集範囲と施策の表示対象をそれぞれ確認。
- **表示済み・閉じた状態**：このブラウザ内の上限と状態を確認。
- **確定状態が不明**：除外factを指定したならfalse/trueを明示して連携。
- **判定値が足りない**：質問と閾値を確認。値を購入率として読まない。
- **モデルエラー・費用上限**：運用者がキー・モデル・上限を確認。

## Previewのテスト値

スタブ環境では「固定のテスト値で判定」「Jevへ未送信」と区別します。ここでの0.95は実モデルの出力ではありません。利用量や速度の実測として扱いません。

## 共有するとき

要求や画面にページ情報・行動情報が含まれます。スクリーンショットやJSONを共有する前に、個人情報・機密・認証情報が含まれていないか確認してください。通常のIssuesへ実閲覧履歴をそのまま貼らないでください。

終了ボタンで診断を閉じます。ユーザー停止やサイト権限の取消でも認可を失います。単なるログアウトだけで、発行済みの診断認可を個別に消去する方式ではありません。

## 初期判断とローカル更新の見分け方

現在ページ・流入ページ・過去の有効閲覧を分けて表示します。ページの初期判断は1回だけです。最低閲覧時間への到達は「有効閲覧へ保存（通信なし）」、イベントや状態の連携もローカル更新として記録します。判定履歴では、要求時点のJSONと応答を確認してください。

診断の接続が初期判断に間に合わなかった場合は、その要求の詳細を後から取り直しません。次のページへ移動して初期判断を確認してください。パネルを開くための追加のJev問い合わせは行いません。

## 閲覧・行動のタイムライン

「閲覧・行動」の上段に、流入から現在までの行動履歴を表示します。初期表示は古い順で、新しい順にも切り替えられます。ページのカードには名称・経路・表示時間を表示し、「取得したページ情報」を開くと詳細を確認できます。現在のページは緑で強調し、過去の有効閲覧と区別します。

診断中に連携された許可済みの操作・状態変更は、ページ閲覧の間に時刻順で表示します。同じページの再訪は別の閲覧です。下段の「その他の計測情報」には、現在ページの取得元、保持している操作・状態、施策の表示回数・閉じた状態をまとめています。

再読み込み後は、保存済みの流入ページと過去の有効閲覧を表示します。保存されていない時刻は「時刻の記録なし」とし、最低閲覧時間未満の途中ページや過去の操作時刻を推測して補いません。診断中の時刻と短い閲覧の記録は、既存の診断バッファ（最大60件・合計1MB）内でのみ保持し、同意撤回・終了・期限切れ・通常の再読み込みで消去します。診断用の時刻・閲覧IDをストレージやAPI要求へ追加しません。
