# セキュリティと秘密情報

## キーを区別する

| 名前                 | 用途                      | 保存先                                         |
| -------------------- | ------------------------- | ---------------------------------------------- |
| CLOUDFLARE_API_TOKEN | 配備・D1・Access等の操作  | 作業環境/CIの秘密管理                          |
| JEV_API_KEY          | Jevの実判定               | Worker/Node.jsの実行時Secret                   |
| ADMIN_TOKEN          | 本番の最初のSuperuser登録 | 実行時Secret。初回後の通常ログインには使わない |
| AUTH_SECRET          | 診断認可の署名            | 環境ごとの独立した実行時Secret                 |

**ビルド用のCloudflareトークンと、アプリ実行時のJevキーは別です。** 値をGit、HTML、JavaScript、通常変数、Issuesへ入れないでください。管理画面にも値を出しません。

Cloudflareの設定では、APIキーを通常のテキスト変数ではなく**Secret**として登録します。APIから設定全体を表示すると、平文変数が出力に混ざることがあります。確認は名前・種類等に限定します。

## パスキーと管理セッション

管理CookieはSecure・HttpOnly・SameSite=Laxで、ブラウザのWeb StorageやURLへ置きません。サーバーはランダムなセッション値のハッシュを保持します。

書き込みではOriginとCSRFを検証し、サイトの権限もサーバーで確認します。ユーザー停止や権限変更は、画面を隠すだけでなくAPIへ反映します。

## Previewの保護

Preview URLは既定では公開です。Cloudflare Accessで担当者を限定し、Worker側でもAccess JWTを検証します。D1、Secret、費用カウンターを本番と分離します。

Accessを設定するAPIトークンの権限は、ログインユーザーのJevSense権限を自動で与えるものではありません。

## 独自コード

サイトと同じ権限で実行されます。コード登録者を管理者に限定し、レビューと確認を行ってください。variablesもブラウザに見える情報です。

## 外部送信とログ

対象ページのメタデータ・URLパス・追加連携を確認し、同意とプライバシー表示を整えます。Jevの保持条件・料金等は提供元へ確認してください。

プロキシやAPMへ要求本文、Cookie、Authorization、診断認可、閲覧履歴を記録しないようにします。CORSのOriginは通常HTTPクライアントから偽装できるため、費用攻撃の認証対策として扱いません。

## 費用と可用性

日次上限と同時実行数を設定します。失敗した実モデル要求も日次上限に算入し、自動再試行しません。アプリ内の上限だけで請求額の厳密な上限を保証するものではありません。

WorkersのIP制限はロケーション単位の近似的な制限です。Node.jsのカウンターはプロセス内で、再起動するとリセットします。

## 漏洩が疑われるとき

該当の提供元でキーを再発行・失効し、使っている環境のSecretを更新します。認証に関する問題では、ユーザー停止やセッション終了も併用します。

AUTH_SECRETの変更は診断認可を無効にしますが、DB参照型の管理セッションをそれだけですべて終了するわけではありません。必要に応じて明示的にセッションを失効してください。
