# トラブルシューティング

## 最初に確認する順番

[同意とタグ](./integration/sdk) → [サイト設定](./guides/sites) → [施策の状態](./guides/campaigns) → [診断パネル](./guides/debugging)の順に確認すると、どこまで処理できているか分かります。

| 症状                               | 確認すること                                                         |
| ---------------------------------- | -------------------------------------------------------------------- |
| タグを入れても通信しない           | SDK読込、同意、サイトID、HTTPS、メタデータ送信、CSP                  |
| ページを開いてすぐオファーが出ない | 初期判断は行うが、有効閲覧数・時間や条件不足なら出さない             |
| JSONは返るが表示しない             | decision、campaign、表示形式、画像読込、独自コードのreportShown、CSP |
| 一度閉じたあと出ない               | ブラウザ内のdismissedと表示上限                                      |
| 設定を保存できない                 | 権限、入力上限、古いrevision、必要なパスキー再認証                   |
| プレビューが拒否される             | Origin・許可/除外経路・施策対象・表示タイトル・期限                  |
| 別サイトが一覧にない               | アカウントのサイト所属                                               |

## パスキーでログインできない

メールとパスキーのアカウントを確認します。正しいHTTPS Originで開き、別の登録済み端末やキーも試してください。localhostとIPは同じRPではありません。

端末を失った場合は[復旧手順](./guides/accounts#端末を失った場合)を使います。メールだけで新しい管理者を登録する公開の復旧APIはありません。

## Accessで入場できない

許可されたメールを使ってください。メールコードが届かない場合は入力、迷惑メール、期限を確認し、必要なら自分で再送します。JevSenseの招待だけではAccessの許可対象は増えません。

入場後もJSONの403が出る場合は、Accessのaudience・発行元・固定AUTH_ORIGINが一致しているか運用者が確認します。個別Deployment URLではなく、固定Preview URLを使います。

## Cloudflareの認証エラー

CLOUDFLARE_API_TOKENとJEV_API_KEYは別です。Tokenの対象アカウントと操作権限を確認します。Secretの「ready」は実APIの許可を保証しません。

アカウント用API Tokenは、ユーザー用の`/user/tokens/verify`だけでは検証できません。`wrangler whoami`またはアカウント用検証APIを使い、401だけで再入力を繰り返さないでください。

Accessアプリを作れない403ではAccess編集権限、D1操作の403ではD1編集権限とDBの接続先を確認します。

## モデルや費用のエラー

| 理由                 | 対応                                               |
| -------------------- | -------------------------------------------------- |
| model_not_configured | 実行時SecretのJEV_API_KEYを確認                    |
| model_error / 502    | キー、利用できるモデル名、提供元の稼働と応答を確認 |
| budget_exhausted     | UTC日単位の費用枠を確認                            |
| busy                 | 同時実行上限を確認                                 |
| rate_limited / 429   | 操作や要求が集中していないか確認し、時間を置く     |

Previewの固定スタブは実モデルの障害確認には使えません。キーを修正するときも、値をログやIssuesへ貼らないでください。

## 本番リリースが停止する

40文字の確認済みコミット、現在のHEAD、未保存の変更、`data/deployments/preview.json`の配備記録を確認します。記録がない場合はPreviewを作り直します。本番へ強制配備してこの確認を迂回しないでください。

## それでも解決しない場合

[Issues](https://github.com/manji6/jev-personalization/issues)に、再現手順、ブラウザ/OS、起きた操作、期待した結果、秘密情報を除いたエラー名を添えてください。Cookie・キー・トークン・フォーム値・実閲覧履歴は共有しないでください。
