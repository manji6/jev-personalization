# 現在ページ・有効閲覧履歴・流入URLと1回の初期判定

状態：Previewでの確認と利用者の本番反映承認を経て、2026-11-03に本番へ反映済み。既存の余白/defer修正も含む。配備したアプリケーションのコミットは`a81e9234700de88440985e70e671f0ff3399b430`。[配備記録](deployment.md)を参照。

## 計測と通信

通常の判定要求は、同意・設定取得後、論理ページ表示の最初の1回だけ。1回には失敗・保留・設定の版違いも含む。`decide()`の重複呼び出し、表示時間到達、visibility、メタ情報変更、track/setFactでは追加の判定要求を送らない。イベント・状態・メタ情報はローカル更新し、次のページの初期判定へ引き継ぐ。隠れたページは最初に表示されるまで初期判定を待つ。再試行のためのポーリングは追加しない。

論理ページは文書読込またはSPAのpathname変更。queryだけの変更やhash変更は新規閲覧とせず、保存する現在URLだけを更新する。queryだけで画面を切り替える独自ルーターはこの初期範囲に含めない。SPAのpathname変更では200ms待ち、設定を再取得してから新ページを計測・判定する。設定のGETは判定POSTと別で、Jevを呼ばない。

現在ページは閲覧済みと認める前から表示判定へ使う。有効閲覧履歴へ加えるのは、可視時間がサイトのminVisibleMsへ到達した時点だけ。滞在時間はその後も更新する。現在ページを履歴へ保存したこと自体は通信の理由にならない。同じタブのsessionStorageを使い、閲覧者のサーバーID・履歴DBは追加しない。

## URLの取得・除外

サイト設定`excludedQueryKeys`へGETパラメータのキーを最大50件、各100文字まで設定する。空ならすべてのGETパラメータを保持する。キーはURLSearchParamsで1回デコードした完全一致、大文字小文字を区別する。値・任意式・正規表現は設定しない。同じキーの重複パラメータもすべて除外する。部分一致・空白の自動変換で別のキーを誤削除しない。

URLのusername/passwordとfragmentは常に除外する。除外はSDKで保存・通信・診断の前に行い、未加工URLをAPIへ送ってから除外する方式にしない。除外がない場合は元のqueryの表記・順序を維持し、除外時も保持するパラメータの値を勝手に切り詰めない。URLは4,096文字まで。超過・不正・対象外URLは省略し、その理由を診断へ出す。URL文字列に対して名称用のメール形式ガードは使わない。未指定のqueryは送信対象になるため、管理画面で説明し、加工後のURLを確認できるようにする。

同じ除外規則を現在ページ・有効履歴・流入ページへ適用する。流入ページは同意後、収集対象として取得できた最初のページ。次ページからcidが消えても保持する。別タブ・別originをまたいだ流入識別や、同意前に離れたページの復元はしない。

除外設定はサイトの公開SDK設定で配信し、版を要求へ含める。変更時は既存のURL履歴・流入情報を整理し、除外した値を送らない。除外を解除しても過去ページで削除した値は復元しない。APIも現在の除外規則で再検証・整形し、Jev・診断応答へ未除外URLを流さない。設定版が異なればJev前で保留し、SDKは必要な設定GETとローカル整理だけを行う。同じページで判定POSTを自動再送しない。

## 要求と互換性

新版SDKは`protocolVersion: 2`、`currentPage`、`entryPage`、有効な`visits`、許可済みactions/facts、delivery、metadataRevision、urlPolicyRevisionを送る。各ページにはpath/name/任意のdescription/type/themesと加工後のurlを持たせる。現在の表示判定に使うページと、興味の根拠になる有効閲覧履歴を混同しない。URLとpathは一致、originは登録済みサイトのものだけを受け付ける。

過去のraw/unqualifiedな保存データは、有効時間を満たす分だけを移行する。保存済みの現在ページを過去の有効履歴へ勝手に昇格させない。表示済み状態と許可済みのイベント・状態は保持する。全体の64KB制限に達する場合は、要求に載せる古い履歴から省き、現在ページ・流入情報を優先する。ローカルの上限は従来どおり50閲覧。

旧SDKの要求は受け付け、現在ページがない要求は従来の履歴仕様で処理する。旧SDKにURL・流入条件の成立を捏造せず、URL条件を評価できない施策は対象外とする。旧SDK自身の通信頻度は配信済みコードの更新・再読込後に新版へ切り替わる。

## 配信条件とJev

施策に判定方式（Jev／URL条件のみ）、任意のURL確定条件、必要な有効閲覧数を設定する。URL条件は現在ページまたは流入ページを対象に、URL全体／GETパラメータの「含む・等しい・前方一致」をコードで評価する。複数条件はAND/ORを明示する。含むは値に対する文字列の部分一致で、大文字小文字を区別する。GETパラメータが複数あればいずれかの値で一致を判定する。

URL条件のみの施策には1件以上の条件が必要で、Jev質問は不要。履歴不要（0件）なら初回訪問でも配信でき、Jevキー・問い合わせ予算を消費しない。Jev方式は確定条件を満たす候補だけを問い合わせる。新規施策は履歴を必須にしない設定を初期値とし、既存施策は未指定ならサイトの必要有効閲覧数を維持する。

Jevのstateにはcurrent_page、任意のentry_page、適格な過去のbrowsing_history_oldest_first、任意のlast_qualified_page、許可済みactions/factsを分けて渡す。現在ページ・流入URLは有効閲覧や関心の確証として扱わない。固定のURL条件は確率で再判定しない。優先順位・表示回数・閉じた状態・除外fact・表示対象pathは従来どおりコードで扱う。

応答待ちにpathname・queryのURL・同意・イベント/確定状態が変われば古い表示応答を使わない。可視時間到達や通常のmeta更新だけでは応答を無効にせず、最初の判定時点の結果として扱う。新ページを開いた間に古い要求が終わった場合、新ページの最初の判定だけを開始する。

## 管理画面と確認

サイトの「ページ情報の取得」に除外キーと加工後URLプレビューを追加する。実ページ確認と人工データ確認も同じURL処理を使う。取得設定の編集はサイト管理者・Superuserのみ。診断では現在ページ・有効履歴・流入情報・ローカル更新と通信を区別する。

テストは初期1回、閾値到達/イベント/meta/visibilityで追加0回、次ページで1回、hidden・SPA・通信中遷移・同意競合・失敗・設定版違い、URL重複/エンコード/除外/fragment/credentials/長さ/保存復元/流入保持、URL確定条件・履歴不要の初期判定・Nodeとworkerd・管理UI・実ページ確認を含める。実Jev呼び出しや本番DB変更は行わない。

新版要求へのalgorithmVersionはpage-context-v2、旧要求はqualified-visits-v1。診断用の別タブだけは管理画面からの認可を最大500ms待ち、初回要求に認可を付ける。追加要求は行わない。
