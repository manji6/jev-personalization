# 施策の判定条件を失わず編集する

施策条件の新規作成・再編集は、現在は[ノード式の詳細設計](condition-graph-design.md)に従います。既存質問を厳密に復元する原則は維持します。

## 復元の境界

編集画面は入力支援フォームを初期表示にする。保存済みjudgmentがあればそれを表示し、questionsだけの場合は定型を厳密に識別する。現在と従来の定型について、案内内容・各条件・質問IDを取り出し、再生成したすべての質問が原文と一致する場合だけ案内内容と条件のフォームへ復元する。判断の組み合わせはcampaign.combinationをそのまま使う。

別々の案内内容を持つ質問、自由記述の質問、定型に似ていても一致しない質問は、原文と質問IDを保持した質問ごとのフォームへ表示する。意味を推測して分解しない。すべての有効な質問を編集でき、JSONだけの初期画面や空の条件へ切り替わらない。生成AIは使用しない。

## 形式と保存

judgmentに任意のkeys・templateVersionを追加し、従来の質問IDと旧定型の文章を保存後も維持する。新規の標準入力は現在の定型を使う。条件の追加・削除では残る質問のIDを維持する。

JSONは明示的な編集方法として残す。切り替え時に現在のフォームを読み取り、JSONを変更しない往復では不完全な下書きも含めて保持する。JSONを変更した場合は古いjudgmentを外し、変更後のquestionsから復元する。文意を持つ原文を古いメタデータで上書きしない。

下書きと配信開始の両方で追加メタデータを検証し、公開後に再読み込みしても同じ入力支援で開く。AND/OR・条件数・質問ID・原文を保持する。既存サイト・施策の一括書き換えは行わない。

## 検証

NodeではAND/OR、1・2・5条件、現在/旧定型、独自ID、改行・引用符、異なる案内、自由記述、1000文字の質問、不完全な下書きを確認する。Chromiumでは5条件ORの定型・旧形式・自由記述で、初回表示→JSON往復→下書き→公開→再読み込み→再編集を通し、すべての質問とID・組み合わせが一致することを確認する。
