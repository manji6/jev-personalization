# オファー表示・サイト共通デザイン 詳細設計

## 設定の責務

site.designにサイト共通の色・文字サイズ・角丸・余白と、modal/floating/barの配置・幅を保存する。campaign.presentationは表示形式と画像のみ表示の選択、contentは文言・画像URLと代替テキスト、targetは表示対象ページを保持する。施策単位のテーマ上書きは作らず、サイトの見た目を一括で変更できるようにする。

旧設定は読み込み時に安全な既定値を補完し、DBスキーマ変更は不要。旧施策はフローティング形式で表示する。設定変更で既存の条件・content・表示回数を消さない。公開サイトの実設定は初期化しない。

## 描画・状態

APIは判定後に施策の内容・表示形式とサイトのdesignを返す。Jevへdesignやコードは渡さない。SDKと管理画面プレビューは共通rendererを利用する。標準形式はShadow DOMでページのCSSから分離し、型と範囲を限定したデザイントークンからCSSを構成する。任意CSSやHTMLの挿入は提供しない。

モーダルは閉じる・Escape・フォーカス復帰に対応する。画像はHTTPS URLと代替テキストを持ち、取得失敗時には標準テキストへフォールバックし、画像のみ形式では表示を中止する。成功した描画でだけブラウザ内の表示回数を更新する。ページ遷移・同意撤回・破棄時に表示とイベントを除去する。APIのshow自体を表示実績と見なさない。

管理画面のプレビューはJevを呼ばず、表示回数を記録しない。サイト共通デザインの変更を選択中施策で即時に確認できる。公開前の画面全体プレビューも提供する。

## 独自JavaScript

site.allowCustomJavaScriptは既定false。許可後のみcustom形式を保存・配信できる。コードは単一の`export function render(context)`（asyncも可）として構文解析し、トップレベルの実行や静的importを受け付けない。関数本体は設置先サイトの権限で動く管理者コードであり、サンドボックスではない。

コードは内容ハッシュ付きの外部ESモジュールとして配信する。eval/new Function/データをコードへ文字列展開する方式は使わない。公開モジュールは対象サイトのOrigin、サイトの許可状態、施策の有効状態、コードハッシュを確認し、非キャッシュで返す。SDKは自分のAPIホストの所定のモジュールURLだけを読み込む。

contextにはcontent、variables、mount、signal、close、reportShownを渡す。履歴・フォーム・APIキー・管理トークンは渡さない。reportShownは描画後に呼び、同じ描画につき1回のみ数える。renderの返り値は後片付け関数。非同期読み込み中のページ遷移や同意撤回でabortし、遅れて返った後片付け関数も実行する。独自コードは任意のDOM操作ができるため、登録者がsignalとcleanupの契約を守る必要がある。

管理画面では独自コードを実行しない。管理トークンへアクセスできる文脈から分離するため、構文確認と編集を提供し、独自コードの表示テストは専用のテストサイトで行う。登録コードと画像URLに秘密情報を含めない。CSPのscript-srcにはAPIホスト、img-srcには利用する画像ホストの許可が必要。

## 管理画面

「サイト設定・共通デザイン」と「施策編集」のタブを分離する。サイト設定はorigins・経路・同意後の送信有効化をフォームから扱えるようにし、JSONを必須にしない。テーマには「このサイトの全施策へ適用」と明示。保存はフォームから1回で行えるようにし、詳細JSON編集との混在は明示的な取り込みで解決する。検証エラーを日本語の項目名とともに表示する。

## 確認項目

旧設定の補完、範囲外CSS/URL/不正コードの拒否、表示対象ページの事前除外、Node/Workersの同一応答、3形式の実ブラウザ描画、閉じる・Escape・フォーカス・画像エラー・SPA・同意撤回、共通テーマの全施策継承、独自コードへの文字列受け渡しと後片付け、デスクトップ/モバイル、管理画面で独自コードが動かないことを検証する。
