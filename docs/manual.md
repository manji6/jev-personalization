# 使い方マニュアル

## 1. 導入担当者：サーバーを準備する

Node.js 24以上でREADMEの手順を実行します。Jevの契約・APIキーを準備し、JEV_API_KEYへ設定します。ADMIN_TOKENは推測困難なランダム値を32文字以上で用意し、秘密管理サービスから渡します。チャット・設定JSON・Gitには書きません。CONFIG_PATHの既定はdata/config.json、PORTは3000、HOSTは127.0.0.1です。外部接続にはapi.typesafe.aiのHTTPS通信を許可してください。

サーバーをHTTPSで提供し、管理画面は社内アクセスやVPN等に制限します。設定用ボリュームは永続化します。起動時に設定が存在しない・不正・キーがない場合は起動に失敗します。サンプルをコピーして初期化してください。

## 2. サイトの送信範囲を決める

`https://your-api.example/admin`を開き、管理トークンを入力して「設定を読み込む」を押します。「導入担当者向け」の詳細設定で、サンプルのdemoサイトを自分のサイトに合わせます。

| 項目                    | 設定例・意味                                                   |
| ----------------------- | -------------------------------------------------------------- |
| id                      | my-site。scriptのdata-siteと一致させる                         |
| origins                 | https://www.example.com。パスや末尾スラッシュを付けない        |
| allowedPathPrefixes     | /articles/ や /products/。公開・非個人ページに絞る             |
| excludedPathPrefixes    | /account、/checkout、/searchなど個人情報を含む経路             |
| metadataEnabled         | タイトル・説明・JSON-LDを確認してからtrueにする                |
| actionNames / factNames | 任意連携で受け付ける操作名・状態名                             |
| minVisibleMs            | 例5000。判断材料として認める最低表示時間。成果保証の値ではない |
| minQualifiedVisits      | 例2。適格閲覧の最低件数。再訪も1件として数える                 |

pathはページのURLパスです。個人情報がパスやメタデータに含まれる場合は、そのページを収集対象から外します。自動除去だけには依存しないでください。`/`を許可するとサイト全体が対象になるため、初期導入では狭く始めます。編集後「確認した設定を保存して配信に反映」を押します。サーバー側の条件変更は次の判断から適用されます。SDK側の経路・送信設定変更はページ再読込後に適用されます。

## 3. scriptを1つ設置する

サイト共通テンプレートまたはタグ管理ツールへ以下を追加します。ページ別の呼出しや属性は不要です。

```html
<script
  defer
  src="https://your-api.example/sdk.js"
  data-site="my-site"
></script>
```

上の例は同意待ちで、勝手に収集しません。CMP等で同意が得られた後に次を実行します。script読み込み完了後に呼び出してください。

```js
await window.JevPersonalization.consent(true);
// 同意撤回時：保存済みタブ内履歴と表示も削除
await window.JevPersonalization.consent(false);
```

サイト側で設置前に必要な同意を確実に取得済みの場合だけ、scriptに`data-consent="granted"`を付ける方法も使えます。CSPのscript-srcにAPIホスト、connect-srcにAPIホストを許可します。HTTPSページで使ってください。API接続先はscriptのホストから自動決定し、別ホストならdata-apiで指定できます。

## 4. マーケター：施策を作成する

1. 管理画面で設定を読み込み、サイトを選んで「施策を追加」を押します。
2. 「誰に、何を伝えたいですか」に口語で書き、「関心のテーマ」に判断したいテーマを短く書きます。例：『導入方法に関心を示す人に導入ガイドを紹介したい』、テーマ『サービスの導入方法』。
3. 「質問案を作る」「上の質問案を取り込む」を押します。現在の変換は単一テーマ向けのテンプレートです。意図を正しく表しているか確認します。
4. 表示タイトル・本文・リンク文言・HTTPSリンク先を入力します。HTMLは使えません。
5. 複数の判断が必要なら質問を1行に1問で編集し、「すべて」または「いずれか」を選びます。1問に複数条件を詰めず、確定条件は導入担当と相談して設定します。
6. 優先順位、表示上限、閾値を設定し、まず停止状態で保存・内容確認します。有効化するときは配信状態を「有効」に変更します。
7. 「編集を設定に反映」→「確認した設定を保存して配信に反映」の順で押します。1サイト最大5施策・合計10問です。

通常の施策作成ではJSONやイベント名の記述は不要です。ただし初期のサイト設定と高度な確定条件は導入担当者が行います。例えば登録済みを除外するには、許可済みfactNamesにregisteredを追加し、施策のexcludeFactをregisteredに設定します。registeredが不明な閲覧者にはその施策を出しません。

## 5. 任意の操作・状態を連携する

閲覧だけで意味が分からない操作のみ、同意後に連携します。

```js
window.JevPersonalization.track("guide_download", true);
window.JevPersonalization.setFact("registered", false);
```

許可リストに登録した名前とboolean/有限のnumberだけ受け付けます。氏名、メール、フォーム入力などは渡さないでください。任意イベントは収集するだけで自動的な確定条件にはなりません。必要な条件はコードまたはexcludeFactで扱います。

## 6. 確認・停止・トラブル対応

適格なページを一定時間表示すると15秒間隔で問い合わせます。対象の場合、ページ末尾に案内が出ます。表示時間は「読んだ時間」の証明ではありません。確認用にはブラウザのNetworkで/v1/decisionの応答を見ます。実閲覧者の履歴を問い合わせチケット等へ貼り付けないでください。

- insufficient_observation：最低時間または閲覧件数が不足。関心なしではありません。
- metadata_not_approved：サイトのmetadataEnabledが無効。
- no_eligible_campaign：停止・上限・閉じた状態・未確定の除外事実などを確認。
- no_match_or_uncertain：確率が設定条件を満たさなかった。正確な心理の否定ではありません。
- model_error：認証・接続・タイムアウト・モデル応答不正。エラーを関心なしと扱いません。
- budget_exhausted / busy / 429：費用上限・同時実行・要求数制限。案内は保留されます。
- origin_rejected：設定originsと実際のサイトオリジンを一致させます。
- config_changed_reload：別の保存が先行。読み込み直して編集してください。

配信停止は施策を「停止」にして反映・保存します。すでに表示中の案内は閉じるかページを再読込してください。サーバーを停止してもサイト本体は動き続けます。同意を撤回するとSDKは送信・表示を止めます。
