# JevSense 使い方マニュアル

このマニュアルはパスキー対応の新管理画面用です。公開中の環境がまだ管理トークン方式なら、切り替え前は[旧版の操作方法](manual-v1.md)を使ってください。新方式の導入は[セットアップ・移行手順](admin-v2-setup.md)を参照してください。

JevSenseは、閲覧から関心や状態を察知・判定し、事前に登録したコンテンツを表示する基盤です。文章やHTMLをAIで生成するサービスではありません。

## ブラウザだけで確認する

[Cloudflare Preview](https://admin-v2-jev-personalization.manji6.workers.dev/admin)で操作できます。許可されたメールのコードでCloudflare Accessへ入り、表示名とパスキーを登録します。本番とは別の確認環境です。初回管理トークンの入力は不要です。[詳しい確認方法](cloudflare-preview.md)をご覧ください。

ヘルプはログイン前の案内、ログイン後のサイドメニュー（狭い画面では本のアイコン）、ホームの案内から別タブで開けます。入力途中の管理画面を残したまま手順を確認できます。

## 1. 公開せずに一通り試す

Node.js24以上を用意し、リポジトリのフォルダーで実行します。

```sh
npm ci
npm run review
```

ブラウザで **http://localhost:4174/admin** を開きます。接続先は`127.0.0.1`限定で、Cloudflareや他の人が開けるURLへ公開しません。localhostはWebAuthnの開発用として利用できます。`127.0.0.1`と入力するとパスキーのRPが異なるため、表示したlocalhostのURLを使ってください。

初回画面で表示名・メール・以下の**確認専用**トークンを入力し、端末のパスキーを登録します。

```text
local-review-only-not-a-production-token
```

これはローカル起動専用の既知の値です。本番に設定しないでください。実際の認証・DB保存・権限・表示処理を動かしますが、通常のJev判定だけは`local-review-stub`（0.95）の固定値です。課金されるJev APIやCloudflareのキーは使いません。

確認用サイトは登録済みで、実ページプレビュー先は **http://localhost:4174/demo** です。アカウントと設定は`data/review.sqlite`に残り、再起動後も使えます。最初から試したい場合はサーバーを終了し、別の新しいDBパスを`REVIEW_DB_PATH`に指定してください。停止はターミナルでCtrl+Cです。

## 2. ログイン・アカウント・メンバー

初回登録した人はSuperuserになります。次回以降はメールアドレスを入力し、パスキーでログインします。端末の顔/指紋/PINやセキュリティキーを使います。管理トークンを共通パスワードとして入力する運用は終了します。

左下のアカウントから表示名を変更できます。表示名は全サイトで共通です。メールはログインIDとして固定します。「別のパスキーを追加」で予備の端末・キーも登録できます。最後のパスキーは削除できません。

「復旧コードを発行・再発行」からコードを安全な場所へ保存してください。値を表示するのは発行時だけです。端末を失った場合はログイン画面の「パスキーが使えない場合」から、メールとコードで新しいパスキーを登録します。復旧完了時は古いパスキー・全ログイン・残りの復旧コードが無効になるので、再度コードを発行してください。コードも使えない場合はSuperuserへ本人確認と復旧リンクの発行を依頼します。

管理者は「メンバー」でメールとサイト権限を指定し、招待リンクを発行して本人へ共有します。メールは自動送信しません。期限は24時間・1回限り。同じメールへ再発行すると以前のリンクは無効です。メールの所有確認を自動で行ったという意味ではありません。

| 権限         | できること                                                     |
| ------------ | -------------------------------------------------------------- |
| Superuser    | 全サイト・ユーザー・環境を管理                                 |
| サイト管理者 | 所属サイトの設定・共通デザイン・メンバー・独自JavaScriptを管理 |
| 編集者       | 所属サイトの標準施策を作成・編集・配信・確認                   |
| 閲覧者       | 所属サイトの設定を参照                                         |

登録済みユーザーは既存のパスキーで招待を受けます。別のサイトへ参加するたびにパスキーを作り直す必要はありません。所属サイトは上部ヘッダーで切り替えられます。重要な変更では、パスキーの再認証を求めることがあります。

## 3. サイトを設定する

「サイト設定」→「基本設定」を開きます。サイトの追加はSuperuserが「JevSense管理」から行います。

- サイト名：ヘッダーなどに表示する名前です。
- 許可するオリジン：例 `https://example.amanohashi.date`。パスや末尾のスラッシュを入れません。
- 収集する経路：例 `/ja/`。前方一致で、1行に1つ指定します。
- 収集しない経路：会員・検索・フォーム・決済など、判断材料から除く経路を指定します。
- メタデータ送信：ページの名称・説明・種類・テーマを確認してから有効にします。
- 有効な閲覧とみなす表示時間：ミリ秒で設定します。短時間表示を判断材料から除く基準です。
- 必要な有効閲覧数：何件の有効な閲覧から判断するかです。
- イベント名・状態名：応募完了・カートあり等を追加連携するときだけ登録します。

「設定を保存」で反映します。計測ポリシーを変更した場合は対象ページを再読み込みしてください。新設サイトはメタデータ送信も施策も無効です。

画面例：[ホーム](images/admin-v2-implemented-home.png) / [施策編集](images/admin-v2-implemented-content.png) / [アカウント](images/admin-v2-implemented-account.png)。

「共通デザイン」では、サイト全体の背景・文字・ボタン色、フォント、文字サイズ、角丸、余白、モーダルの幅と背面、フローティングの幅・位置・余白、通知バーの位置を調整します。右のプレビューをモーダル・フローティング・通知バーに切り替え、変更をその場で確認できます。保存すると配信中を含むそのサイトの標準施策へ適用します。

## 4. 施策を作る

「施策一覧」→「新しい施策」を開きます。

### 対象者・条件

1. **施策名**：管理用の名前です。サイト上には表示しません。
2. **何を伝えたいですか？**：案内する内容です。例「吸汗速乾ポロシャツの特集を案内する」。
3. **どんな人に届けたいですか？**：判断したい1つの関心・状態です。例「吸汗速乾機能のあるポロシャツに関心がある」。
4. 表示された「Jevに送る判定質問」が意図どおりか確認します。

質問は入力文を固定の型に当てはめて作ります。生成AIは使いません。複数の判断があるならJev条件ノードを追加し、URL条件とAND/ORノードでつなぎます。出力は下、入力は上の端子です。「編集」で入力し、「変更を保存」で図へ反映します。「削除」や右クリックのメニューで削除でき、「元に戻す」も使えます。別の質問の回答を参照する条件は書けません。正確なページ一致・表示回数・確定状態の除外は配信設定へ分けます。

「対象者判定の厳しさ」は「広めに判定」「標準」「慎重に判定」から選びます。内部のしきい値は順に0.6・0.7・0.85で、初期設定は「標準」です。慎重にするほど表示対象になりにくくなります。購入率や施策効果を設定するものではありません。

細かく調整する場合は「詳細設定（しきい値を調整）」のスライダーと数値入力を使います。範囲は0.5〜0.99。判定値がこの値を**上回る**場合に対象です。3段階に一致しない既存の値は「カスタム設定」として保持し、自動で丸めません。下書き保存と配信開始の流れは同じです。

「この設定を試す」では、登録済みサイトの現在・流入URLと仮の判定値で条件を試せます。Jev APIや利用回数は使いません。実際の推論・配信制約・表示の確認は、動作確認と実ページプレビューを使います。

### 表示コンテンツ

モーダル、フローティング、通知バーから選び、表示タイトル・メッセージ・ボタン文言・HTTPSのリンク先・HTTPS画像・代替テキストを設定します。画像だけにする場合は画像URLと代替テキストが必要です。共通デザインはサイト設定から引き継ぎます。

独自JavaScriptは、サイト管理者が基本設定で許可したサイトで利用できます。コードもブラウザへ配信する文字列も公開情報として扱ってください。信頼できるコードだけを登録し、秘密情報や個人情報を埋め込まないでください。

```js
export function render(context) {
  const element = context.mount.ownerDocument.createElement("div");
  element.textContent = context.variables.message || context.content.title;
  context.mount.append(element);
  context.reportShown();
  // context.mode は通常配信なら "delivery"、確認表示なら "preview"
  return () => element.remove();
}
```

contextにはcontent、variables、mount（ShadowRoot）、signal、close、reportShown、modeを渡します。`reportShown()`は実際に表示できたときに呼びます。独自の計測や状態変更は`mode === "preview"`のとき実行しないよう、作者が対応してください。コードはサイトと同じ権限で動きます。

### 配信設定と保存

表示するパスを全許可ページ・完全一致・前方一致から選びます。ホームページだけなら完全一致で`/ja/`などを指定します。これは閲覧情報の収集範囲とは別です。表示回数、優先順位、確定状態の除外も設定します。

「下書き保存」は作業の保存です。既存の配信は変わりません。配信は施策一覧から行います。下書きのある行の「本番へリリース」で内容の概要を確認し、「本番へリリースする」で初めて公開設定へ反映します。停止・再開も一覧からできます。途中の下書きは「下書きを破棄」で明示的に削除できます。

同時編集で競合した場合は、一覧を読み直して内容を確認してください。古い下書きが残る場合は必要な入力を控えてから破棄し、最新の施策から編集を始め直します。

## 5. 実際のページへ確認表示する

施策一覧の「プレビュー」を押し、確認するページURLを入力して「ページを開いて確認」を押します。保存済みの下書きがあればそれを優先します。未保存の編集は含みません。

- 対象サイトに最新版のSDKタグが必要です。メタデータ送信や施策の通常配信を有効にする前でも確認できます。
- 許可されたオリジン・収集/除外経路・施策の表示対象に一致するURLを使います。
- 今回の操作で開いたタブへ、5分以内・1回だけ有効な確認チケットを渡します。
- Jevを呼ばずに表示します。通常の閲覧履歴・表示回数・閉じた状態は更新しません。
- 閉じる・ページ移動で終了します。再読み込みや同じURLのコピーで強制表示は引き継ぎません。

管理画面も開いたままにしてください。SDK未設置、CSP、COOP、ポップアップ制限などで失敗した場合は、表示を直してから新しいプレビューを起動します。引き換えた後の失敗でも古いチケットは再使用できません。

## 6. ページへのタグ設置と通常の動き

「動作確認」に選択中サイトのタグ例を表示します。

```html
<script
  defer
  src="https://YOUR-API-HOST/sdk.js"
  data-api="https://YOUR-API-HOST"
  data-site="YOUR-SITE-ID"
></script>
```

サイト共通で1つ設置し、利用者の同意を取得した後で呼びます。

```js
window.JevPersonalization.consent(true);
```

すでに同意取得が済むサイトは`data-consent="granted"`も使えます。撤回は`consent(false)`でブラウザ内の対象履歴も消去します。SDKの読み込み完了前に呼ばないよう、タグのロードとCMPの順序を調整してください。

閲覧順序・表示中の時間・ページ情報は自動取得し、sessionStorageへ保持します。標準はOGP → title・metaの順に取得します。JSON-LDは「サイト設定 → ページ情報の取得」のカスタムルールで利用します。取得設定がない既存サイトは移行まで従来のJSON-LD優先を維持します。APIに常時送信し続けるポーリングは行いません。ページごとの初期表示時に1回だけ判断します。有効閲覧時間への到達・イベント・状態変更はブラウザ内に保存し、次ページの初期判断で使います。

任意連携は、サイト設定で登録した名前だけが対象です。

```js
window.JevPersonalization.track("guide_download");
window.JevPersonalization.setFact("registered", true);
```

フォームの入力値、氏名、メール、ページ全文などは渡さないでください。

## 7. 診断と全体管理

「動作確認」で対象URLを開くと、サイト上の診断パネルから自動取得データ・実際のAPI要求・Jevへの質問・判定結果を確認できます。通常の配信を観察する機能で、強制表示プレビューとは目的が異なります。利用者同意も通常どおり必要です。詳細は[診断パネル](debugging.md)を参照してください。

Superuserの「JevSense管理」では全サイト・全ユーザー・復旧・環境名・実モデル名・日次呼び出し上限・同時実行上限・最近の管理操作を確認できます。APIキーや認証用シークレットの値は管理画面に出しません。モデル名は利用できる実モデル名を確認して指定してください。日次上限0で新しいJev判定を止められます。

成果集計、購入率表示、メール自動送信、画像アップロードは今回の対象外です。実機のパスキーでの最終確認項目は[受入テスト手順](admin-v2-validation.md)をご覧ください。

## サイトごとのJev接続と利用数

「Jev連携」はサイト管理者/Superuser専用です。共通キー・専用キー・利用停止を選び、専用キーは暗号化保存します。保存後は値を再表示せず、空欄で再保存すると現在値を保持します。共通/停止へ切り替えると専用キーを削除します。

「利用状況」でUTC日別の呼び出し開始・正常応答・エラー・結果未確定、最近100件のモデルと遅延を確認できます。閲覧者データは記録しません。スタブ・強制プレビューは件数外です。課金はJev側で確認します。

[詳しい画面操作](../help/guides/jev.md)と[暗号化キーの初期設定・更新](../help/operations/jev-keys.md)を参照してください。

## サイト別のページ情報取得

「サイト設定 → ページ情報の取得」で、標準またはカスタムを選びます。右側へURLを入力すると、未保存の設定案を実ページのSDKで確認できます。Jev判定・通常配信・履歴保存は行いません。計測同意・メタデータ送信有効化・最新版SDKが必要です。確認は5分間で、設定案を変えたら開き直します。

[取得方法の設定と確認手順](../help/guides/sites.md#ページ情報の取得と実ページ確認)と[詳細設計](metadata-extraction-design.md)を参照してください。

## URLの取得と条件

サイト設定の「ページ情報の取得」で、取得しないGETパラメータのキーを1行ずつ指定できます。空ならURLのGETパラメータをすべて保持します。除外は大文字小文字を区別したキーの完全一致で、同じキーの値をすべて取り除きます。URLの資格情報と#以降は常に除きます。加工後のURLは右側で確認できます。

施策では現在・流入ページのURL条件をコードで照合できます。例：流入ページのGETパラメータcidにrunnerを含む。URLだけで判定する方式ならJevへの問い合わせは発生しません。必要な過去の有効閲覧数を0件にすれば初回訪問でも判定できます。詳細は[ヘルプの施策設定](../help/guides/campaigns.md)をご覧ください。

## 接続設定と施策の再編集

APIキーは各サイトの「Jev連携」に登録します。未設定・停止・暗号化設定の不足は選択中サイトの通知から確認できます。共通キーは廃止しました。詳しくは[接続設定](../help/guides/jev.md)を参照してください。

新規作成・編集ともノード式で開きます。既存施策のAND/OR、質問ID、質問原文は保持します。条件グラフのJSONもコピー・編集でき、不正な接続や循環は拒否します。詳細は[ノード式の施策設定](../help/guides/campaigns.md)と[設計](condition-graph-design.md)をご覧ください。
