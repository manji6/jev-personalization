# JevSense 使い方マニュアル

JevSense（ジェブセンス）は、閲覧からユーザーの意図や文脈を察知・判定し、事前登録したオファーを届けるパーソナライズ基盤です。判断にはJevを使います。文章・HTML・コードをJevに生成させる仕組みではありません。

画面例：[施策編集](images/admin-desktop.png) ／ [サイト共通デザイン](images/site-design.png) ／ [スマートフォン](images/admin-mobile.png)。サンプル設定での表示例です。

## 1. 最初に接続する

[管理画面](https://jev-personalization.manji6.workers.dev/admin)で、Cloudflareへ登録したADMIN_TOKENを入力し「設定を読み込む」を押します。初回構築は[Cloudflare手順](cloudflare.md)、Node.js版の起動はREADMEを参照してください。公開URLとSDKのJevPersonalizationというAPI名は継続して使えます。

## 2. サイトを設定する

「サイト設定・共通デザイン」タブを開きます。このタブは選択中サイト全体の設定です。

- **対象サイトのオリジン**：例 `https://adobe.customer-experience.dev`。パスや末尾の / は含めません。
- **収集を許可する経路**：例 `/ja/`。1行に1つ、公開ページの経路を指定します。
- **収集しない経路**：例 `/ja/login`、`/ja/commerce/member`、`/ja/commerce/cart`、`/ja/commerce/search`。個人情報を含むページを除外します。
- **同意後のメタデータ送信**：ページのタイトル・説明・構造化データを確認してから有効にします。
- **最低表示時間と閲覧数**：短時間表示を判断材料から除くための基準。初期値5000ミリ秒（5秒）・2件は仮の出発点で、関心や成果を保証する値ではありません。

複数サイトを扱う場合は「別のサイトを追加する」からIDを指定します。追加直後は送信・配信とも無効です。サイトIDはタグのdata-siteと一致させます。

設定は「保存して配信に反映」でまとめて保存します。通常操作でJSONを書く必要はありません。サイトの収集範囲を変更した場合は、対象ページを再読込してSDKへ新しい設定を読み込ませてください。

## 3. サイト共通のベースデザインを整える

同じタブの「サイト共通のベースデザイン」で以下を設定します。

| 共通・形式           | 調整できるもの                                                                |
| -------------------- | ----------------------------------------------------------------------------- |
| 全形式共通           | 背景色、文字色、ボタン色、ボタン文字色、ゴシック/明朝、文字サイズ、角丸、余白 |
| モーダル             | 最大幅、背面の暗さ                                                            |
| フローティングバナー | 右下/左下、幅、画面端との余白                                                 |
| アナウンスメントバー | 画面上部/下部への固定                                                         |

このデザインはサイトの標準オファーすべてに適用されます。施策ごとに同じ見た目を作り直す必要はありません。施策には文言や画像を設定し、見た目はサイト設定を継承します。

右側のプレビューでモーダル・フローティング・バーとPC/スマートフォンの幅を切り替えられます。「画面全体でプレビュー」では実際の配置を確認できます。プレビューはJevへ問い合わせず、表示回数も加算しません。小さなプレビュー枠は表示幅を縮めた確認用であり、実サイトのCSPや周囲のデザインまで再現するものではありません。

## 4. 施策を作成する

「施策を編集する」タブで、施策を選ぶか「施策を追加」を押します。

1. **誰に届けるか**を口語で記述。例「吸汗速乾ポロシャツに関心を示す人へ特集を案内したい」。
2. 「文章から質問案を作る」を必要に応じて開き、施策の意図と判断したい関心のテーマを入力。テーマはオファー名ではなく「吸汗速乾ポロシャツ」などの判断対象です。質問案を取り込み、意図が合っているか確認します。任意の文章を完全自動分解するものではありません。
3. **表示形式**を選び、タイトル・メッセージを入力。リンクを付ける場合はリンク文言とHTTPS URLを入力します。リンクなしの文字だけの通知も可能です。
4. 画像を使う場合はHTTPS画像URLと代替テキストを設定。画像だけのバナーにする場合は「画像のみ」を選びます。画像はURL参照方式で、ファイルアップロードは未提供です。
5. **オファーを表示するページ**を設定。トップページ `/ja/` だけなら「完全一致」と `/ja/` を指定します。閲覧履歴の収集経路とは別の設定です。
6. 質問のAND/OR、確率の閾値、優先順位、表示回数、配信状態を確認します。
7. 「保存して配信に反映」を押します。フォームの変更を1回で保存できます。

施策の切替時には編集中の内容を一時保持しますが、サーバーへは保存ボタンを押すまで反映しません。「設定を読み込む」は保存済みの内容へ戻す操作です。

配信停止は「配信状態」を「停止」にして保存します。表示済みのオファーをサーバーから強制的に消す機能ではなく、次の判断から対象外にします。

## 5. 表示の動作

- モーダルは中央に表示し、閉じるボタン・Escapeで閉じます。キーボードのフォーカスを案内内へ移し、閉じた後に戻します。
- フローティングバナーは画面の隅、バーは上部または下部に固定表示します。ページ本文を押し下げるレイアウト変更は行いません。
- 標準表示はShadow DOMでサイトのCSSから分離します。細部はサイト共通デザインで設定し、任意CSSやHTMLは受け付けません。
- 画像取得に失敗した場合、通常のオファーは文字を表示します。画像のみの場合は表示せず、表示回数も加算しません。
- 表示成功時にだけブラウザ内の回数を更新します。閉じた状態も同じタブ内で保持します。ページ遷移・同意撤回時は表示を片付けます。

## 6. 独自JavaScriptを使う（導入担当者向け）

「サイト設定・共通デザイン」の「高度な連携・独自コードの許可」で許可し、施策の表示形式を「独自JavaScript」にします。登録コードは設置先サイトの権限で実行されます。レビュー済みのコードだけ使ってください。コードと変数はブラウザへ配信されるため、キー・トークン・個人情報を含めてはいけません。

コードは次の単一のrender関数をエクスポートする形で記述します。トップレベルの実行文や静的importは使えません。

```js
export function render({ content, variables, mount, signal, reportShown }) {
  const button = document.createElement("button");
  button.textContent = variables.label || content.title;
  button.addEventListener(
    "click",
    () => {
      window.location.assign(content.url);
    },
    { signal },
  );
  mount.append(button);
  reportShown();
  return () => button.remove();
}
```

変数欄には文字列のJSONオブジェクトを入力します。

```json
{ "label": "ポロシャツ特集を見る" }
```

| 引数        | 意味                                                                    |
| ----------- | ----------------------------------------------------------------------- |
| content     | 施策のタイトル、本文、リンク、画像。閲覧履歴や秘密情報は含まない        |
| variables   | 変数欄で設定した文字列。コードへの文字列展開ではなくデータとして渡す    |
| mount       | 表示用のShadowRoot。必要な要素をappendする                              |
| signal      | ページ遷移・同意撤回・破棄でabortする。イベントや非同期処理の中止に使う |
| close       | オファーを閉じ、閉じた状態を保持する                                    |
| reportShown | 描画できた後に呼ぶ。同じ表示では1回だけ加算                             |

返り値として後片付け関数を返してください。async関数も使えますが、非同期処理ではsignalを確認し、破棄後にDOM操作しないでください。独自コードの副作用をシステムが完全に取り消すことはできません。

管理画面では独自コードを実行しません。専用のテストサイトで確認してください。標準の共通デザインも自動適用しません。content等のデータを使い、自分で見た目を作れます。外部ESモジュールとして配信するため、設置先のCSPでAPIホストをscript-srcに許可してください。evalやunsafe-evalは不要です。

## 7. タグ設置・同意連携

サイト共通テンプレートへ1つ設置します。サイト設定タブにもタグが表示されます。

```html
<script
  defer
  src="https://jev-personalization.manji6.workers.dev/sdk.js"
  data-site="demo"
></script>
```

demoは自分のサイトIDへ変更します。SDK読み込み完了後、同意取得時に呼び出します。

```js
window.JevPersonalization.consent(true);
// 同意撤回
window.JevPersonalization.consent(false);
```

同意取得済みの場合だけタグを配信する仕組みならdata-consent="granted"を付けて自動開始できます。CSPはscript-src/connect-srcにAPIホスト、img-srcにオファーの画像ホストを許可してください。標準デザインは対応ブラウザでConstructable Stylesheetsを使い、サイトのstyle-srcにunsafe-inlineを要求しません。古いブラウザのstyle要素へのフォールバックではサイトのCSPでスタイルが拒否される場合があります。

初回の表示判断は、同意取得とサイト設定の読み込みが済んだ時点ですぐに行います。すでに十分な閲覧履歴があれば、その履歴で判定できます。初めて訪れた人など情報が足りない場合は保留し、設定した最低表示時間に達したところで再判定します。

その後の判断要求はページ遷移、最低表示時間への到達、連携した操作・状態の変化、ページ情報の更新時だけです。何も変わらなければ定期的な通信はしません。タブが非表示の間やオファー表示中も追加要求を止めます。滞在時間の計測・保存はブラウザ内で続けます。タグの変更は不要です。

## 8. 任意連携と高度な設定

操作・状態はサイト側の許可リストへ登録してから連携します。booleanまたは有限数のみを使い、フォーム入力や自由入力の値を渡さないでください。

```js
window.JevPersonalization.track("guide_download", true);
window.JevPersonalization.setFact("registered", false);
```

許可されたtrackと、値が変わったsetFactは自動で再判定を依頼します。同じ値をsetFactしても通信しません。短時間に続いた更新はまとめて送信します。通常はdecide()を別途呼ぶ必要はありません。decide()を明示的に呼んでも、同じ判断材料での重複要求は送信しません。

「導入担当者向け：サイト・施策の詳細設定」のJSONを直接編集する場合は「JSONの変更を取り込む」を押してから保存します。未取り込みのJSONがある状態ではフォーム保存を止め、変更が消えないようにしています。通常の利用ではJSONは不要です。excludeFactなど追加の確定条件は詳細JSONで扱います。

## 9. 実サイトでのデバッグ

管理画面の「実サイトで動作確認」で、タグを設置したページのURLを入力し「このサイトで動作確認」を押します。別タブに診断パネルが開き、計測情報・送信したJSON・Jevの判定・表示結果を確認できます。管理画面も開いたまま使ってください。15分間有効で、通常の同意・配信条件を守ります。Chrome拡張やタグの追加は不要です。

使い方・記録の範囲・接続できない場合は[デバッグパネルの説明](debugging.md)を参照してください。

## 10. トラブル対応

- **保存エラー**：画面下部の項目パスと説明を確認。画像のみなら画像URLと代替テキスト、独自コードならサイト側の許可と構文を確認します。
- **反応がない**：同意、origins、許可経路、送信の有効化、施策の有効化、表示対象パス、最低表示時間・閲覧数を確認します。
- **レスポンスはshowなのに出ない**：SDKの最新版への再読込、画像エラー、CSP、閉じた状態を確認。SDKは最大5分キャッシュされます。
- **表示回数・履歴を確認**：対象サイトのSession Storageのjev:v1:サイトIDを確認します。個人の履歴をチケットや通常ログへ貼り付けないでください。
- **model_error**：Jev接続・認証・タイムアウトを確認。関心なしとは別の状態です。
- **config_changed_reload**：別の保存が先行。設定を読み込み直して編集します。

標準表示は現行のChrome/Edge/Firefox/Safariを想定し、自動ブラウザテストはChromiumで実施しています。実サイトのCMP・CSP・スマートフォンでの受入確認も行ってください。
