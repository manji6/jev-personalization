# サイト専用キー・条件フォーム復元の検証

2026-11-03。[サイト専用キー設計](site-only-jev-design.md)・[フォーム復元設計](question-restoration-design.md)に対応する。

- Node/SQLite・HTTP・DOM：74件成功。
- workerd/D1/Durable Object：18件成功。
- Chromium・仮想パスキー・実画面操作：93件成功。
- 画面の合成アカウントでPC・390pxの通知と接続設定を確認。APIキー入力値をHTMLや再取得APIへ表示しない。
- 現在/旧定型・自由記述の5条件ORで、入力フォーム→JSON往復→下書き→配信開始→再読み込み→再編集を確認。全質問・質問ID・AND/ORの一致を検証。
- 条件の削除・追加後も残る質問IDを維持し、ANDへの変更を保持。長いフォームで選択メニューのスクロールがページ側を動かして閉じる挙動も修正。
- APIキー未設定・旧instance行・他サイト・利用停止・復号不能で実通信なし。廃止済みの環境共通キーが存在しても使用しない。登録済みのサイトキーだけが使われる。
- 未設定状態は所属する閲覧者にも通知し、設定先は管理者だけに表示。サイト切り替え、保存後の状態更新を確認。
- 履歴0件・URL条件だけの施策はサイトキーなしで配信対象を選べる。

実Jevへは接続せず、合成キーと模擬上流だけで検証した。Previewの固定判定も有料APIを使用しない。既存の暗号文・設定・利用記録を一括変換するDB移行は追加していない。

本番反映は、利用者が「動作確認後Previewもリリースして問題なければ本番へリリース」と承認した範囲で行う。URL条件とJevを任意のAND/ORグループで組み合わせる新しいUIは別のモック検討であり、この改修の実行ロジックへ含めない。
