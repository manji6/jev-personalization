# 管理画面の独自ドメインへの切り替え

2026-11-03。正式な管理originを`https://jevsense.amanohashi.date`へ変更する。Cloudflareの独自ドメイン接続と`AUTH_ORIGIN`を一致させ、RP IDも正式ホストから固定で得る。Hostを使った自動的な認証許可は追加しない。

GET/HEADの管理画面・認証画面・管理アセット・rootへの別originアクセスを、設定済みoriginへ302で案内する。HTTPはHTTPSへ移動する。認証や管理APIへの書き込みでは従来の正確なOrigin検証を継続する。SDK・公開設定・判断APIの既存接続先は維持する。Previewのorigin・DB・Accessは変更しない。

本番には既存のSuperuserとパスキーが各1件あり、復旧コードは未発行だった。利用者から再登録の意向が示されたため、アカウントや施策を削除せず、既存の復旧手順で新ドメインへパスキーを登録し直す。ADMIN_TOKENの初回登録を再開しない。

切り替え前に、利用者自身が旧管理画面のアカウントから復旧コードを発行・保存する。利用者の保存完了の回答と、DBに未使用コードが8件あることを確認してから、本番DBを非公開でバックアップし、認証先を切り替えた。コードの値はチャットや運用ログへ渡さない。

切り替え後は`https://jevsense.amanohashi.date/admin/recover`へ進み、登録済みメールと保存済みの復旧コード1つを使って、新しいパスキーを登録する。ユーザー・施策・公開設定・サイトキー・旧パスキーは手動で削除しない。再登録が成功すると、標準の復旧処理が旧資格・ログインを失効させる。

復旧コードをすべて失った場合は、既存の環境運用者向け手順で短命なrecovery invitationを発行できる。nonceは32byteの暗号学的乱数、DBにはSHA-256/base64urlのハッシュのみを保持し、期限は5分、1回限りとする。対象者・有効な発行者・監査を記録する。今回このリンクは発行していない。

復旧URLは対象者だけへ渡す。リポジトリ・ヘルプ・運用ログへ値を記録しない。期限切れの場合は再発行する。復旧コード・リンクを失った環境運用者向けの既存手順は`admin-v2-setup.md`に記載する。
