# サイト専用Jevキーと設定状態の表示

## 目的と互換性

Jevへの実通信には、サイトIDに結び付いた暗号化APIキーだけを使う。環境のJEV_API_KEYや旧instanceモードへ戻る経路をNode・Workersの双方から除く。共通キーを各サイトへコピーする移行は行わない。既存のsiteモードの暗号文・revision・AAD・利用記録は保持する。

旧instance行または行なしはunconfiguredとして読み取る。新しい保存APIはsiteとdisabledのみ許可する。既存DBのCHECKには読取互換性のためinstanceが残るが、新規保存・送信には使わない。過去の利用記録のinstanceは「廃止済みの共通キー」として表示する。新しい実通信のkey_sourceは常にsite。DBの破壊的移行や既存Secretの削除は今回のPreview作業では行わない。

## 実行と保管

従来どおりAES-256-GCM、JEV_KEYRING、サイトIDとrevisionを含むAADで保存する。キーをAPI応答・HTML・ログに返さない。欠落・停止・暗号化鍵の不足・復号不能なら、Jevへの通信と利用記録・予算消費の前に保留する。他サイトのキーや共通キーへ切り替えない。

旧トークン方式のWorkersでも、管理DBにある当該サイトのキーだけを読み取る。管理DBや暗号化鍵がない環境は保留する。Nodeの旧サーバー起動には共通キーを渡さず、実運用にはパスキー管理方式を使う。

URL条件だけの施策は引き続きJevキー不要。Previewの固定値判定とローカル確認の明示的なテスト用モデルは実通信をしないため別扱いにし、画面で区別する。

## 管理APIと画面

サイト管理者・Superuserが接続状態の詳細、キーの登録・更新・停止、利用記録へアクセスする。編集者・閲覧者にはサイト取得APIを通して設定状態の分類だけを返し、キー管理APIは許可しない。状態は未設定・停止中・暗号化設定不足・復号不能・保存済みを区別する。保存済みはJev側での有効性や残高を保証しない。状態取得でJevへ接続しない。

選択中サイトの各ページに、未設定の内容と対応先を示す通知を置く。サイト管理者には「Jev連携を設定」、編集者・閲覧者には「サイト管理者へ依頼」の案内を出す。メタデータ送信の無効、配信中の施策なしも項目として示す。URL条件だけの施策がある場合、キー未設定はJev方式の施策への制限と説明し、すべて停止とは表示しない。サイト切り替え、再読み込み、キー保存・停止・配信設定更新後に状態を更新する。

## 導入と検証

ProductionはJEV_KEYRINGを必須にし、初期設定手順から共通APIキーの登録を取り除く。各サイトの管理者が管理画面でAPIキーを入力する。旧共通キーに依存するサイトは、リリース後にキーを登録するまでJev方式の施策を配信できない。

検証：共通環境変数が存在しても未設定・旧instance・他サイト・停止・破損キーでは通信0件。保存済みサイトキーの継続利用、サイト間の認可、CAS、再認証、書込時だけのキー入力、過去ログの表示、状態通知と権限・切り替え・PC/モバイルを確認する。Nodeとworkerdの実通信は模擬APIで検証し、有料Jev呼び出しは行わない。Previewで確認後にProduction反映を承認する流れを維持する。
