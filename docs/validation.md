# 検証記録

実施日：2026-10-30（日本時間）。Node.js 24.19.0。

## 自動テスト

`npm run check`：SDKビルドと32件の単体・HTTP統合・DOMテスト。

- 判断エンジン7件：短時間除外、生履歴の維持、未確定事実、配信上限、all/any、確率閾値境界、優先順位、不正応答、経路制限、入力制限、要確認の質問案、短時間の現在ページが判断材料へ混入しないこと。
- API・永続化9件：許可Origin、CORS preflight、未知フィールド、本文制限、管理認証、Jev障害・不正確率の保留、設定再読込、古い編集と並列編集の競合拒否、Bearerアダプター、同時実行上限、費用上限、レート制限。
- SDK7件：JSON-LD @graph/mainEntity/@id、単一型と曖昧な候補、壊れたJSON-LDのフォールバック、簡易個人情報抑制、同意前の無通信、同意撤回、許可された事実・操作だけの保存、SPAとquery除去、経路除外、保存データの再検証と期限切れ。

`npm run test:browser`：Chromiumで33件。

- 配布ビルド済みscriptから同意・実時間計測・判断要求・Shadow DOM表示・表示回数更新・同意撤回まで。
- CSP付き管理画面での認証、口語から質問案の生成、取り込み、フォーム編集、保存、再読込。
- 刷新した管理画面のデスクトップ・スマートフォン表示、入力に連動するプレビュー、接続・編集状態、横方向のはみ出しがないこと。
- Workersで配信した管理画面をブラウザから操作し、編集内容がD1経由で保存・再読込できること。

オファーの単体テスト5件では、旧設定の補完とサイトごとの独立したデザイン、CSS/URL/画像設定の検証、表示対象ページ、共通テーマ、独自コードの許可・構文・ハッシュ配信を確認。Node.jsのAPIテストにもモジュール配信のOrigin・停止状態の検証を追加。

ブラウザのオファーテスト11件では、標準3形式、モーダルのフォーカス・Escape、画像成功/失敗、テーマ継承、同意撤回・遅延モジュール、管理画面で独自コードを実行しないこと、JSONの未保存変更保護、サイト追加を確認。

SDKの判断タイミングのブラウザテスト11件を追加。初回即時要求、既存履歴による即時表示、最低表示時間の到達で1回だけの再判定、10分相当の待機でも定期要求が増えないこと、明示的なdecide()の重複抑止、操作・状態のまとめ送りと同値の無視、非表示時間の除外、通信中の更新と古い応答の破棄、SPAの遷移・除外経路・メタデータ更新、同意撤回、障害時に定期リトライしないこと、同じURLへ戻った場合の古い応答の破棄、pagehide/pageshow、非表示中の応答を通信せず再表示時に描画することを確認。時間の長いケースはPlaywrightの仮想時計を使用。Node・Workers両方の公開設定APIがminVisibleMsを返すことも検証。

`npm run test:cloudflare`：workerd上で8件。

- Assets配信、CSP・セキュリティヘッダー、APIと静的ページの経路分離。
- 実D1エミュレーターのprimary read、同時編集のCAS、初期データの再適用で既存設定が戻らないこと。
- モックしたJevへの判断要求、入力選別、CORSとpreflight、未知フィールド、認証、本文サイズ制限。
- 共有の日次クォータ、モデル障害時の保留、Durable Objectでの同時実行制御とランタイム再起動後のカウンター保持。
- 初回D1設定コマンドと、D1 IDが未設定のときリモートデプロイを開始しないこと。

`npm run cf:migrate:local`で初期マイグレーションが適用できることを確認。`npm run cf:dry-run`でWorker、5つの静的ファイル、D1・Durable Objects・Rate Limiting・AssetsのバインディングがWranglerで検証できることを確認。アップロード・本番リソース作成は行っていない。

ブラウザは実Chromiumで、Node.js版はFastifyのHTTP注入、Workers版はMiniflareのworkerdへ接続し、Jev応答はモック。TLS配備、外部ネットワーク、本番負荷の再現ではない。通常サンドボックスではChromium起動がEPERMとなったため、許可された実行モードで再実施した。

`npm audit`：既知の脆弱性0件（開発依存を含む、検証時点）。将来の安全性を保証しない。GitHub Actionsでもビルド、単体/統合テスト、ブラウザテスト、production依存の監査を実施する。

## 実Jev検証の範囲

先行実験の6件は[実験レポート](../experiments/adobe-ja/README.md)と要求・応答記録に保存した。本実装のテストでは追加の有料Jev要求は行っていない。実モデルjev-1.14.0、先行6件の遅延146〜329ms。短時間閲覧の除外をAPIの前処理に持たせる根拠として用いた。

## 未検証・制限

- Dockerfileのコンテナビルド・起動、本番のTLSプロキシ・永続ボリュームは未実施。
- CloudflareのD1作成、リモートマイグレーション、Wranglerでの初回デプロイ、公開health・管理画面・SDKのHTTP 200を確認済み。GitHub Buildsによる自動デプロイと、利用者が行うSecrets登録後の実Jev呼び出しは未確認。[初回配備記録](deployment.md)を参照。
- Firefox/Safari、実CMP、実サイトへのSDK設置、モバイル、BFCacheの実ブラウザ往復や大量の動的JSON-LDは追加確認が必要。
- 同時実行・費用・レート制限の機能テストは実施したが、長時間の負荷試験・SLO評価ではない。
- 合成履歴での成功は、利用者の心理の正解率・施策効果・コンバージョン改善を証明しない。
- 口語の任意の条件式を完全自動で分解する機能は未実装。初期版は単一テーマの質問案を人が確認する。
- サーバーに閲覧履歴を保存しないことと、Jev提供元のデータ保持条件は別問題。契約条件を確認してから実データを送信する。

本番で使うサイトの設定と運用環境の受入試験は、公開前に運用担当者と実施する。

## デバッグパネルの検証

診断認可・Node APIのテスト4件では、管理認証、署名改ざん、期限・サイトID・Originの範囲、URLのクエリ除去、認可なしの詳細非公開、実際のモデル入力との一致、情報不足時の未実行、使用量の許可項目だけの公開を確認。SDKテストには取得元がページの送信JSONへ混入しない検証を追加。workerdの診断テスト1件では、同じ認可・要求と実際の前処理・モック応答を通して両実装の対応を確認。

ブラウザの診断テスト7件では、管理画面から別Originのページを開くpostMessage連携、取得元と判定値の表示、フォーム値を送信しないこと、同意前の無計測・無判断、同意撤回による記録削除、通信中の撤回後の応答破棄、通常遷移後の再接続、終了後の再接続停止、認可をURL・ブラウザストレージに残さないこと、期限切れ、偽造メッセージ、通常訪問者への非表示、モバイルの幅と折りたたみを確認。使用するAPI・SDKは配布ビルドとworkerdで、Jevはモック。Firefox/Safari、実サイトのCOOP・CMP・CSPの組合せは別途受入確認が必要。
