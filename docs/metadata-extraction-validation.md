- Node：65件。既存53件に、抽出器・版管理・同意競合8件、管理API・確認用認可4件を追加。ビルドも成功。
- Cloudflare workerd/D1：15件。新しいマイグレーション、公開設定、旧版要求の保留、一度限りの引き換え、Origin/CORSを確認。
- Chromium：82件。全件成功後、Previewデモの取得値とSDKの同意競合対策を追加し、影響範囲の12件を再確認。管理画面の実WebAuthn、通常配信、診断、取得確認、ヘルプを含む。
- ヘルプ：24ページをビルドし、内部リンク・アンカーを検証。コード整形チェックも成功。

抽出器では標準のOGP→title/meta、空/不正/個人情報形式の候補の繰り下げ、JSON-LDを標準では読まないこと、SKU欠損/0、説明欠損、AND/OR、順序、型の完全一致、同一オブジェクトへの条件と出力の結合、曖昧な複数候補、mainEntity、外部参照・一覧の非展開、文字数・深さ・候補数の上限、危険なプロパティ参照の拒否を確認した。

取得ルールの版変更では過去の閲覧だけを破棄し、表示済み状態・許可済みイベント・確定状態を保持した。SDKが変更を検出したときの限定的な設定再取得、重複判定の抑制、同意撤回と遅延した設定応答の競合も確認した。

管理APIはサイト管理者以外の拒否、CSRF、CASによる同時保存、公開設定に秘密を含めないこと、古い版の要求をJev前で止めることを確認した。確認用の認可はURL/origin/path/nonce、期限、ログアウト、権限変更、収集範囲変更、メタデータ無効化で検証した。同時引き換えは1件だけ成功し、設定と閲覧者履歴を変更しなかった。

ブラウザでは未保存の設定案での実ページ確認、同意前は引き換え・収集しないこと、meta/JSON-LD更新、明示再取得、query/hash保持、偽メッセージの無視、設定案の変更で古い結果を消すこと、未保存の変更の破棄、5分の期限、ページ遷移、参照権限を確認した。1440px・390pxで横方向のはみ出しがないことを確認した。Access保護付きの同一originのPreviewでも、Cookieを保持したままSDKと連携し、Jev・通常の閲覧履歴保存を行わず結果を返すことを確認した。

## Previewでの最終確認手順

1. 保護付き[Preview管理画面](https://admin-v2-jev-personalization.manji6.workers.dev/admin)へログインする。
2. `preview-demo`サイトを選び、「サイト設定 → ページ情報の取得」を開く。既存サイトは切り替えて保存するまで従来動作を維持する。
3. 「標準の自動取得」を選び、右側のURLへ`https://admin-v2-jev-personalization.manji6.workers.dev/demo`を入力して確認する。ページ名は「夏のポロシャツ特集」。
4. 保存せず「サイト独自のルール」へ切り替え、同じURLを開き直す。初期候補なら「商品詳細：吸汗速乾ポロシャツ」になり、条件に使ったSKUの生値は返らない。
5. 候補の順序・接頭辞・説明欠損の方針を編集する。設定案を変えると古い結果は消える。開き直して結果を確認する。
6. 必要なら「変更内容を確認 → 保存する」。これはPreviewのサイト設定だけを変更する。Productionへのリリースは別操作。

本番サイトへ設置済みのSDKが旧版の場合、新機能の確認はできない。まずPreview内のデモで確認する。COOP・CSP・CMP・サイト固有のメタ情報は運用するサイトで別途確認する。

デプロイのコミット・日時・IDは、`npm run cf:preview`がローカルの`data/deployments/preview.json`へ記録する。Previewは専用DBとCloudflare Accessを使い、ProductionのDB・キー・配信設定を変更しない。ヘルプの変更はソースへ含め、Production確認前にGitHub Pagesへ自動公開しない。
